# 虚函数与对象模型

> 一句话结论：虚函数的多态依赖「每个对象一个 vptr、每个类一份 vtable」实现；虚调用是运行时查表，构造和析构期间 vptr 只指向当前正在构造/析构的类，不会派发到派生类。

## 为什么考 / 怎么考

这是中级 C++ 面试区分度最高的一题。初级能背出「虚函数实现多态」，中级要能讲清 vptr/vtable 的归属、对象布局、构造析构期间的行为，以及虚析构为什么是必须的。面试官常见的追问链是：

1. 虚函数怎么实现的？
2. vtable 在内存哪里？每个类一份还是每个对象一份？
3. 构造函数里调用虚函数会怎样？
4. 为什么基类析构函数要写成 virtual？
5. 多重继承下有几个 vptr？

## 原理

### 1. 多态成立的三个条件

- 存在继承关系；
- 派生类**重写**（override）基类的虚函数，函数签名一致；
- 通过**基类指针或引用**调用该虚函数。

只满足前两条、用对象直接调用，仍然是静态绑定，不构成运行时多态。

### 2. vtable 与 vptr

编译器为每个「含有虚函数的类」生成一张虚函数表（vtable），表里按声明顺序存放该类各虚函数的地址。每个该类的**对象**里，编译器会隐式插入一个指向本类 vtable 的指针，叫 vptr。

- vtable 属于类，所有对象共享同一份；通常放在只读数据段（`.rodata` 或 `.data.rel.ro`），具体位置由实现决定。
- vptr 属于对象，64 位下占 8 字节，通常位于对象起始处（标准不规定布局，这是实现细节）。
- 虚调用 `p->f()` 编译成「取 p 的 vptr → 按偏移取 vtable 中的函数指针 → 调用」，这就是动态绑定。

### 3. 构造 / 析构期间的虚调用

对象构造时，vptr 是**分阶段**被设置的：执行到哪个类的构造函数，vptr 就指向哪个类的 vtable。

```cpp
#include <iostream>

class Base {
public:
    Base() { f(); }              // 此时 vptr 指向 Base 的 vtable
    virtual ~Base() { f(); }     // 进入 Base 析构体前，vptr 已被重置为 Base
    virtual void f() { std::cout << "Base::f\n"; }
};

class Derived : public Base {
public:
    void f() override { std::cout << "Derived::f\n"; }
};

int main() {
    Derived d;   // 构造和析构各调用一次 f()，输出两次 Base::f
}
```

所以「构造/析构中调用虚函数」不是简单的「多态失效」，而是**虚调用被派发到当前正在构造/析构的那个类**。在构造或析构中调用**纯虚函数**是未定义行为，通常会直接 terminate。

### 4. 为什么基类析构函数必须是 virtual

通过基类指针删除派生类对象时：

```cpp
#include <iostream>

class Base {
public:
    virtual ~Base() { std::cout << "~Base\n"; }
};

class Derived : public Base {
public:
    ~Derived() override { std::cout << "~Derived\n"; }
};

int main() {
    Base* p = new Derived;
    delete p;   // 先 ~Derived，再 ~Base
}
```

如果 `~Base` 不是虚函数，`delete p` 只调用 `~Base`，派生类的析构函数不会执行，派生类持有的资源泄漏，行为未定义。因此：**只要类可能被当作基类使用，析构函数就应该是 virtual**。

### 5. 对象大小

- 空类大小为 1 字节（保证不同对象地址不同）。
- 含虚函数的类，对象里多一个 vptr：64 位下 `sizeof` 至少为 8；若还有 `int` 成员，通常是 16（vptr 8 + int 4 + 对齐填充 4）。

```cpp
#include <iostream>

class Empty {};
class WithVirtual { public: virtual void f() {} };
class IntAndVirtual { int x; public: virtual void f() {} };

int main() {
    std::cout << sizeof(Empty) << '\n';         // 1
    std::cout << sizeof(WithVirtual) << '\n';   // 64 位下 8
    std::cout << sizeof(IntAndVirtual) << '\n'; // 64 位下 16
}
```

### 6. override、final 与 RTTI

- `override`：显式声明「我在重写基类虚函数」，签名不一致时编译报错，避免写错参数导致意外隐藏。
- `final`：修饰虚函数表示禁止继续重写，修饰类表示禁止继承；也给编译器去虚化（devirtualization）提供依据。
- RTTI：`typeid` 和 `dynamic_cast` 依赖对象的动态类型信息，通常通过 vtable 附近的 type_info 指针实现（实现细节，标准未规定）。

### 7. 对象切片

派生类对象赋值给基类**对象**（不是指针/引用）时，只拷贝基类子对象，vptr 变成基类的，派生部分被切掉：

```cpp
#include <iostream>

class Base {
public:
    virtual void f() { std::cout << "Base\n"; }
};

class Derived : public Base {
public:
    void f() override { std::cout << "Derived\n"; }
};

int main() {
    Derived d;
    Base b = d;   // 切片
    b.f();        // 输出 Base
}
```

多态只能通过指针或引用使用，传参时尽量用 `const Base&`。

## 高频追问

**Q1：vtable 存放在哪里？每个类一份还是每个对象一份？**
A：每个含有虚函数的类一份，通常放在只读数据段；对象里只存一个指向它的 vptr。不是每个对象一份。

**Q2：虚函数可以是内联函数吗？**
A：语法上可以。但当调用点只能看到基类指针/引用时，编译器无法确定动态类型，必须查表，无法内联。只有在能确定动态类型（如对象直接调用、`final`、LTO 去虚化）时才可能内联。

**Q3：构造函数可以是虚函数吗？**
A：不能。虚函数依赖 vptr，而对象在构造完成前 vptr 尚未建立到最终类型；语言也不允许构造函数是 virtual。

**Q4：析构函数可以是纯虚函数吗？**
A：可以，而且必须提供函数体，否则派生类析构时链接会失败。纯虚析构常用于「要求类抽象、但仍有公共清理逻辑」的场景。

**Q5：为什么基类析构函数要 virtual？**
A：通过基类指针 `delete` 派生类对象时，只有虚析构才会动态派发到派生类析构，再调用基类析构；否则派生部分不会被析构，行为未定义。

**Q6：空类为什么大小是 1？含虚函数后为什么变大？**
A：大小至少为 1 是为了让不同对象有不同地址；含虚函数后需要存放 vptr，64 位下至少 8 字节，再加成员和对齐。

## 易错点与加分点

- 别说「构造/析构中虚函数失效」——准确说法是 vptr 指向当前类，派发到当前类。
- 别在构造/析构中调用纯虚函数，这是 UB，不是「调用基类实现」。
- `override` 不是可有可无的装饰，它能抓住签名不一致导致的「重载而不是重写」。
- 虚函数调用有间接寻址开销，但通常不是性能瓶颈；真正的热点是缓存不友好和无法内联。
- 多重继承下，派生类对象可能含有多个 vptr，对应不同基类子对象；细节见「构造析构与多继承」篇。
- vtable 布局是实现定义的，不要依赖具体偏移写代码。
