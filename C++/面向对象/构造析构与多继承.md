# 构造析构与多继承

> 一句话结论：构造顺序是「虚基类 → 直接基类（声明顺序）→ 成员（声明顺序）→ 构造函数体」，析构严格逆序；多继承会让不同基类子对象位于不同偏移，指针转换需要地址调整，菱形继承用虚继承消除重复基类。

## 为什么考 / 怎么考

这道题同时考对象模型、生命周期和继承设计。中级面试常从「构造顺序」问起，再追到虚析构、多继承指针调整、菱形继承和对象切片。典型追问链：

1. 构造和析构的顺序是什么？
2. 为什么基类析构函数要 virtual？
3. 多继承下 `A*` 和 `B*` 指向同一对象，地址为什么不同？
4. 菱形继承的问题怎么解决？
5. 什么是对象切片？

## 原理

### 1. 构造与析构顺序

构造一个对象时，顺序固定为：

1. 虚基类（按继承图的深度优先、从左到右）；
2. 直接非虚基类（按声明顺序）；
3. 非静态数据成员（按声明顺序）；
4. 构造函数体。

析构顺序完全相反：先执行析构函数体，再逆序析构成员，再逆序析构基类，最后虚基类。

```cpp
#include <iostream>

struct Base1 {
    Base1() { std::cout << "Base1\n"; }
    ~Base1() { std::cout << "~Base1\n"; }
};
struct Base2 {
    Base2() { std::cout << "Base2\n"; }
    ~Base2() { std::cout << "~Base2\n"; }
};
struct Member {
    Member() { std::cout << "Member\n"; }
    ~Member() { std::cout << "~Member\n"; }
};

struct Derived : Base1, Base2 {
    Member m;
    Derived() { std::cout << "Derived body\n"; }
    ~Derived() { std::cout << "~Derived body\n"; }
};

int main() {
    Derived d;
}
```

输出顺序：`Base1`、`Base2`、`Member`、`Derived body`，然后 `~Derived body`、`~Member`、`~Base2`、`~Base1`。

### 2. 虚析构

通过基类指针 `delete` 派生类对象时，只有虚析构才会动态派发到派生类析构，再调用基类析构；否则派生部分不会被析构，行为未定义。

```cpp
#include <iostream>

struct Base {
    virtual ~Base() { std::cout << "~Base\n"; }
};
struct Derived : Base {
    ~Derived() override { std::cout << "~Derived\n"; }
};

int main() {
    Base* p = new Derived;
    delete p;   // 先 ~Derived，再 ~Base
}
```

析构函数**可以**是纯虚函数，但必须提供定义，否则派生类析构时链接失败：

```cpp
#include <iostream>

struct Base {
    virtual ~Base() = 0;   // 纯虚析构
};
Base::~Base() { std::cout << "~Base\n"; }   // 必须提供定义

struct Derived : Base {
    ~Derived() override { std::cout << "~Derived\n"; }
};

int main() {
    Base* p = new Derived;
    delete p;
}
```

### 3. 多继承与 this 指针调整

多继承下，每个基类子对象按声明顺序放在派生类对象的不同偏移处。把 `Derived*` 转成某个基类指针时，编译器会加上相应偏移，所以不同基类指针的数值可能不同。

```cpp
#include <iostream>

struct A { int a = 1; };
struct B { int b = 2; };
struct C : A, B { int c = 3; };

int main() {
    C obj;
    A* pa = &obj;
    B* pb = &obj;

    std::cout << (static_cast<void*>(pa) == static_cast<void*>(pb)) << '\n'; // 0
}
```

如果基类有虚函数，派生类对象里可能包含多个 vptr，分别服务于不同基类子对象。

### 4. 菱形继承与虚继承

```text
    A
   / \
  B1 B2
   \ /
    D
```

如果 `B1` 和 `B2` 都普通继承 `A`，`D` 对象里会有两份 `A` 子对象，访问 `A` 的成员产生二义性。用虚继承让 `A` 只保留一份：

```cpp
#include <iostream>

struct A { int a = 1; };
struct B1 : virtual A { int b1 = 2; };
struct B2 : virtual A { int b2 = 3; };
struct D : B1, B2 { int d = 4; };

int main() {
    D x;
    x.a = 10;   // 只有一份 A，无二义性
    std::cout << x.a << ' ' << sizeof(D) << '\n';
}
```

虚继承的代价：对象里通常多一个 `vbptr`（虚基类表指针），访问虚基类成员要经过间接寻址；虚基类由最派生类负责初始化。

### 5. 对象切片

派生类对象按值赋给基类对象时，只拷贝基类子对象，派生类部分被切掉，vptr 也变成基类的，多态失效：

```cpp
#include <iostream>

struct Base {
    virtual void f() { std::cout << "Base\n"; }
};
struct Derived : Base {
    void f() override { std::cout << "Derived\n"; }
};

void take(Base b) { b.f(); }   // 按值传参：切片

int main() {
    Derived d;
    take(d);        // Base
    Base& r = d;
    r.f();          // Derived
}
```

多态必须通过指针或引用使用；接口参数优先 `const Base&`。

### 6. 委托构造与继承构造（C++11）

```cpp
#include <iostream>

struct Base {
    explicit Base(int) { std::cout << "Base(int)\n"; }
};

struct D1 : Base {
    D1() : D1(0) {}          // 委托构造：委托给同类的另一个构造函数
    D1(int x) : Base(x) {}
};

struct D2 : Base {
    using Base::Base;        // 继承构造：直接复用基类构造函数
};

int main() {
    D1 a;
    D2 b(1);
}
```

### 7. 析构函数与异常

析构函数默认是 `noexcept`。如果析构过程中抛出异常，而栈正在展开，会直接 `std::terminate`。因此析构函数应吞掉异常或记录日志，不要把可能抛出的操作放在析构里。

## 高频追问

**Q1：构造和析构的顺序？**
A：构造：虚基类 → 直接基类（声明顺序）→ 成员（声明顺序）→ 函数体；析构完全逆序。

**Q2：为什么基类析构函数要 virtual？**
A：通过基类指针删除派生类对象时，虚析构才能派发到派生类析构，避免派生部分资源泄漏和未定义行为。

**Q3：多继承下 `this` 指针为什么要调整？**
A：不同基类子对象位于派生类对象的不同偏移，指针转换时编译器加上偏移，保证基类指针指向正确的子对象。

**Q4：菱形继承的问题怎么解决？**
A：用虚继承（`virtual` 基类），让最派生类只保留一份共享基类子对象；代价是 `vbptr` 和间接访问。

**Q5：什么是对象切片？**
A：派生类对象按值赋给基类对象时，只复制基类子对象，派生部分丢失，虚调用退化为基类版本。

**Q6：析构函数可以是纯虚函数吗？**
A：可以，但必须提供函数体（定义），否则派生类析构时链接失败。纯虚析构常用于让基类抽象，同时保留公共清理逻辑。

**Q7：析构函数能抛异常吗？**
A：默认 `noexcept`；抛出会导致 `std::terminate`，尤其栈展开期间。析构函数不应抛出异常。

## 易错点与加分点

- 构造顺序按「声明顺序」而不是初始化列表顺序。
- 基类析构没写 virtual，却通过基类指针删除派生对象。
- 以为多继承下所有基类指针地址相同。
- 菱形继承不用虚继承，导致二义性或两份状态。
- 按值传递基类参数造成切片，多态失效。
- 能说出虚继承的代价（`vbptr`、间接访问、最派生类初始化），不是「免费的」。
