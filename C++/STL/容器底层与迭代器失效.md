# 容器底层与迭代器失效

> 一句话结论：迭代器失效的规则由容器的内存结构决定——连续内存的 `vector` 一扩容就全部失效，节点式容器只失效被删节点，`unordered_map` 的 rehash 只失效迭代器而不失效指针/引用。

## 为什么考 / 怎么考

「容器底层 + 迭代器失效」是中级面试最爱挖的坑：写起来都能跑，出问题却往往是未定义行为。面试官常沿着一条代码问下来：

1. `vector` 扩容时发生了什么？
2. 扩容后原来的迭代器/指针/引用还能用吗？
3. `map` 的迭代器为什么稳定？
4. `unordered_map` rehash 后什么失效、什么不失效？
5. 边遍历边 `erase` 怎么写才对？

## 原理

### 1. vector：连续内存与成倍扩容

`vector` 用一块连续内存保存元素，`size()` 是元素个数，`capacity()` 是已分配空间能容纳的个数。

- 当 `size() == capacity()` 再插入时，申请一块更大的内存，把旧元素**移动或拷贝**过去，再释放旧内存。
- 扩容倍数是实现相关的：libstdc++（GCC）通常按 2 倍增长，MSVC 通常按 1.5 倍增长。
- 按倍数扩容保证尾部插入的**均摊 O(1)**：n 次插入的总搬移次数是 O(n)。

`reserve(n)` 只预留容量，不改变 `size()`；`resize(n)` 改变元素个数，新元素会被值初始化。扩容会搬移全部元素，因此**所有指向旧内存的迭代器、指针、引用全部失效**。

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;
    v.reserve(100);                 // 容量 100，size 仍为 0
    std::cout << v.capacity() << ' ' << v.size() << '\n'; // 100 0

    v.resize(10);                   // size 变为 10，元素值初始化为 0
    std::cout << v.capacity() << ' ' << v.size() << '\n'; // 100 10
}
```

### 2. deque：分段连续 + 中控数组

`deque` 由多段固定大小的连续块组成，另有一个「中控数组」（map of blocks）存放指向各块的指针。

- 两端插入删除 O(1)，随机访问 O(1)（两次间接寻址）；
- 中间插入删除 O(n)；
- 两端插入会**使所有迭代器失效**，但指向已有元素的引用和指针仍然有效（标准保证）；
- 中间插入删除会使迭代器、引用、指针全部失效。

### 3. list：双向链表

- 每个元素独立分配节点，插入删除 O(1)（已知位置）；
- 不支持随机访问，`std::sort` 不能用于 `list`，要用成员 `sort()`；
- 节点分散，缓存不友好，遍历通常比 `vector` 慢；
- 只有在删除某个元素时，指向该元素的迭代器才失效。

### 4. map / set：红黑树

- 底层是自平衡二叉搜索树（红黑树），查找/插入/删除 O(log n)；
- 中序遍历天然有序，支持范围查询（`lower_bound` / `upper_bound`）；
- 节点独立分配，插入删除不会移动其他节点，因此**除被删除元素外，其他迭代器保持有效**。

### 5. unordered_map / unordered_set：哈希表

- 哈希桶 + 链地址法（标准不规定实现，libstdc++/libc++ 用链表）；
- 平均 O(1)，最坏 O(n)（所有键冲突到同一个桶）；
- 当负载因子 `size() / bucket_count()` 超过 `max_load_factor()`（默认 1.0）时触发 **rehash**：重建桶数组，元素重新分布；
- **rehash 使所有迭代器失效，但指向元素的指针和引用仍然有效**——因为节点本身没有移动，只是桶数组重建了；
- `erase` 只使被删除元素的迭代器失效。

### 6. 迭代器失效规则总表

| 容器 | 插入 | 删除 |
|---|---|---|
| `vector` | 扩容：全部迭代器/指针/引用失效；未扩容：插入点及之后失效 | 删除点及之后失效 |
| `deque` | 两端插入：全部迭代器失效，引用/指针有效；中间插入：全部失效 | 删首/尾元素：仅被删元素及尾后迭代器失效；删中间元素：全部失效 |
| `list` | 不失效（被删元素除外） | 只失效被删除元素 |
| `map` / `set` | 不失效 | 只失效被删除元素 |
| `unordered_map` / `unordered_set` | rehash：迭代器全部失效，指针/引用有效；不 rehash：不失效 | 只失效被删除元素 |

> 记法：**连续内存 → 搬家就全废；节点内存 → 只废被删节点；哈希 → rehash 只废迭代器，不废指针/引用。**

### 7. 正确写法

边遍历边删除时，用 `erase` 的返回值更新迭代器：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5};

    for (auto it = v.begin(); it != v.end(); ) {
        if (*it % 2 == 0) {
            it = v.erase(it);   // erase 返回下一个有效迭代器
        } else {
            ++it;
        }
    }
}
```

按值删除一批元素，用 erase-remove idiom：

```cpp
#include <algorithm>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 2, 4};
    v.erase(std::remove(v.begin(), v.end(), 2), v.end());
    // v == {1, 3, 4}
}
```

`remove` 只把不需要删除的元素前移，返回新的逻辑尾部；`erase` 再真正删除尾部区间。

`map` 的迭代器在插入/删除其他元素时保持稳定：

```cpp
#include <iostream>
#include <map>

int main() {
    std::map<int, int> m{{1, 10}, {2, 20}};
    auto it = m.find(1);
    m[3] = 30;        // 插入新节点，不影响 it
    m.erase(2);       // 删除其他节点，不影响 it
    std::cout << it->second << '\n'; // 10
}
```

`unordered_map` rehash 后引用仍有效、迭代器不能再用：

```cpp
#include <iostream>
#include <unordered_map>

int main() {
    std::unordered_map<int, int> m;
    for (int i = 0; i < 100; ++i) m[i] = i;

    auto it = m.find(42);
    int& ref = it->second;       // 保存引用

    m.rehash(1000);              // 触发 rehash，it 失效
    std::cout << ref << '\n';    // 引用仍然有效
    // std::cout << it->second;  // 错误：it 已失效
    (void)it;
}
```

## 高频追问

**Q1：`vector` 为什么按倍数扩容，而不是每次加固定大小？**
A：按固定大小扩容时，n 次插入的总搬移是 O(n²)；按倍数扩容，搬移总量是等比级数 O(n)，均摊到每次插入是 O(1)。

**Q2：`reserve` 能减少拷贝吗？**
A：能。提前 `reserve(n)` 可以避免多次扩容搬移；但它不改变 `size()`，只改变 `capacity()`。

**Q3：`unordered_map` 什么时候 rehash？**
A：插入导致负载因子超过 `max_load_factor()`（默认 1.0）时自动触发；也可以手动 `rehash(n)` 或 `reserve(n)`。

**Q4：`map` 的迭代器为什么稳定？**
A：红黑树是节点式结构，插入/删除只改指针关系，不移动已有节点；只有被删除元素的迭代器失效。

**Q5：范围 for 中 `erase` 会怎样？**
A：范围 for 底层持有迭代器，`erase` 后继续 `++` 是未定义行为。应改用 `it = c.erase(it)` 的显式循环。

**Q6：`vector` 扩容后，原来的指针还能用吗？**
A：不能。元素被搬到新内存，旧指针、引用、迭代器全部失效。

**Q7：`deque` 两端插入为什么会让迭代器失效？**
A：`deque` 的迭代器内部保存了当前块的位置信息，两端插入可能新增块或改变中控数组，迭代器的内部状态失效；但元素本身没有搬移，所以引用和指针仍有效。

## 易错点与加分点

- 把 `reserve` 当成 `resize`：`reserve` 不创建元素。
- 在 `vector` 循环里缓存 `end()`，插入后继续用。
- 认为 `unordered_map` rehash 会让所有元素引用失效——实际只有迭代器失效。
- 在范围 for 里 `erase`，这是面试官最爱抓的未定义行为。
- `list` 的 `sort` 要用成员函数，不能传 `std::sort` 的迭代器。
- 知道扩容倍数的实现差异，并明白标准不规定具体倍数。
