# 移动语义与右值引用

> 一句话结论：`std::move` 本身不移动任何东西，它只是把表达式转换成右值引用；真正的资源转移发生在移动构造函数/移动赋值里。移动后的对象处于「有效但未指定」状态。

## 为什么考 / 怎么考

移动语义是 C++11 最核心的变化，中级面试常从「STL 容器扩容时为什么快」切进来，考你有没有真正理解值类别和所有权转移。典型追问链：

1. 左值和右值怎么区分？
2. `std::move` 到底做了什么？
3. 移动构造函数为什么要标 `noexcept`？
4. `std::forward` 和 `std::move` 有什么区别？
5. 返回值写 `return std::move(x)` 有什么问题？

## 原理

### 1. 左值、右值与将亡值

- **左值（lvalue）**：有名字、可取地址、生命周期较长的表达式，例如变量 `x`、`*p`、`arr[0]`。
- **纯右值（prvalue）**：临时对象或字面量，例如 `42`、`std::string("hi")`、`x + y` 的结果。
- **将亡值（xvalue）**：本来有身份、但即将被移走的对象，典型是 `std::move(x)` 的结果。它是「右值」的一种。

右值引用 `T&&` 可以绑定到右值（纯右值或将亡值），不能绑定到左值。`const T&` 既能绑左值也能绑右值，这是 const 引用的特殊规则。

一个容易踩的点：**具名的右值引用变量本身是左值**。

```cpp
#include <iostream>
#include <string>
#include <utility>

int main() {
    std::string s = "hello";
    std::string&& r = std::move(s);   // 这里只是类型转换
    std::cout << r << '\n';           // r 仍有名字，使用它时是左值

    std::string t = std::move(s);     // 这里才真正调用移动构造
}
```

### 2. std::move 的真实语义

标准库的实现大致是：

```cpp
#include <type_traits>
#include <utility>

template <typename T>
constexpr std::remove_reference_t<T>&& my_move(T&& t) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(t);
}
```

它只做类型转换，不读取、不修改、不释放任何资源。资源转移发生在接收端：移动构造或移动赋值。

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t n) : data_(new int[n]), n_(n) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other) : data_(new int[other.n_]), n_(other.n_) {
        std::copy(other.data_, other.data_ + n_, data_);
        std::cout << "copy\n";
    }

    Buffer(Buffer&& other) noexcept : data_(other.data_), n_(other.n_) {
        other.data_ = nullptr;   // 关键：源对象置空，避免双重释放
        other.n_ = 0;
        std::cout << "move\n";
    }

    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            n_ = other.n_;
            other.data_ = nullptr;
            other.n_ = 0;
        }
        return *this;
    }

private:
    int* data_;
    std::size_t n_;
};

int main() {
    Buffer a(10);
    Buffer b = std::move(a);   // 调用移动构造
    Buffer c(5);
    c = std::move(b);          // 调用移动赋值
}
```

移动后源对象仍可析构、可重新赋值，但它的值不应再被依赖——标准称之为「有效但未指定状态」（valid but unspecified state）。

### 3. 为什么移动构造要标 noexcept

`std::vector` 扩容时要把旧元素搬到新内存。它使用 `std::move_if_noexcept`：

- 如果元素的移动构造是 `noexcept`，就用移动，快且不会中途抛异常；
- 如果移动构造可能抛异常，而拷贝构造可用，就退化为拷贝，以保证强异常安全。

所以移动构造不标 `noexcept`，可能让 `vector` 扩容悄悄变成拷贝，性能下降。

```cpp
#include <type_traits>

struct Good { Good(Good&&) noexcept {} };
struct Bad  { Bad(Bad&&) {} };

static_assert(std::is_nothrow_move_constructible_v<Good>);
static_assert(!std::is_nothrow_move_constructible_v<Bad>);
```

### 4. 完美转发与 std::forward

模板参数 `T&&` 在发生类型推导时是**万能引用**（forwarding reference），既能绑左值也能绑右值。配合 `std::forward<T>` 才能把实参的值类别原样传给下一层：

```cpp
#include <iostream>
#include <utility>

void sink(int&)  { std::cout << "lvalue\n"; }
void sink(int&&) { std::cout << "rvalue\n"; }

template <typename T>
void relay(T&& v) {
    sink(std::forward<T>(v));   // 保持值类别
    // sink(v);                 // v 有名字，永远是左值，只会匹配 int&
}

int main() {
    int x = 1;
    relay(x);   // lvalue
    relay(2);   // rvalue
}
```

区别：`std::move` 无条件转成右值；`std::forward<T>` 按模板参数 `T` 决定转成左值还是右值。

### 5. RVO / NRVO

- **RVO（返回值优化）**：返回纯右值临时对象时直接构造在调用方位置；C++17 起对纯右值强制省略。
- **NRVO（具名返回值优化）**：返回函数内局部变量时，编译器可以直接把它构造在调用方位置，省掉一次移动/拷贝。NRVO 是允许的优化，不保证发生。

```cpp
#include <string>

std::string make() {
    std::string s = "hello";
    return s;                // NRVO：通常不调用移动/拷贝
}

std::string make_bad() {
    std::string s = "hello";
    return std::move(s);     // 阻止 NRVO，反而多一次移动
}
```

**对返回值写 `std::move` 是反模式**：它把局部变量变成右值引用表达式，破坏 NRVO 的适用条件。

## 高频追问

**Q1：移动构造函数为什么常写 `noexcept`？**
A：`vector` 等容器扩容时用 `move_if_noexcept` 决定移动还是拷贝；移动构造不是 `noexcept` 时，为了保证强异常安全会退回拷贝，失去移动带来的性能收益。

**Q2：`std::move` 对 const 对象为什么退化为拷贝？**
A：`std::move(const T&)` 得到 `const T&&`，而移动构造的参数是 `T&&`，不能绑定 `const T&&`，只能匹配拷贝构造。所以对 const 对象「移动」实际上是拷贝。

**Q3：万能引用和右值引用有什么区别？**
A：`T&&` 出现在模板参数推导（或 `auto&&`）语境时是万能引用，能绑左值也能绑右值；`std::string&&` 这种具体类型的右值引用只能绑右值。`const T&&` 也不是万能引用。

**Q4：移动赋值需要处理自赋值吗？**
A：建议处理。`x = std::move(x)` 是合法但结果未指定的；如果实现先释放资源再从源对象窃取，自赋值会先把自己的资源释放掉，导致错误。标准库通常用 `if (this != &other)` 或先交换。

**Q5：`std::forward` 为什么必要？**
A：函数参数 `T&& v` 一旦有了名字就是左值。不 `forward` 的话，无论调用方传左值还是右值，下一层都只会看到左值，无法触发移动。

**Q6：移动后的对象还能用吗？**
A：能析构、能重新赋值，但值处于有效但未指定的状态，不应再读取。标准容器移动后通常为空，但不保证。

**Q7：RVO 和 NRVO 的区别？**
A：RVO 针对返回临时对象（纯右值），C++17 起强制省略；NRVO 针对返回具名局部变量，是允许的优化，编译器可以不执行。

## 易错点与加分点

- 把 `std::move` 当成「执行移动」是最大的误解：它只是类型转换。
- 移动构造里忘记把源对象的指针置空，会导致双重释放。
- 移动构造没有标 `noexcept`，容器扩容性能悄悄退化。
- 对返回的局部变量写 `std::move`，阻止 NRVO。
- 移动后继续读取源对象的值，是典型的未定义预期。
- 万能引用只发生在类型推导语境；`const T&&`、具体类型 `T&&` 都不是。
