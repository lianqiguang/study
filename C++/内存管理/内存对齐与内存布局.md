# 内存对齐与内存布局

> 一句话结论：结构体的大小由成员的对齐要求和最大对齐补齐决定；调整成员顺序可以减少 padding；真实对象的布局还会被 vptr、继承和虚继承改变。

## 为什么考 / 怎么考

「这个结构体占多少字节」是中级面试的经典开场，往下会追问 padding 的成因、`alignas`/`offsetof` 的用法、缓存行，以及多继承下的对象布局。典型追问链：

1. `sizeof` 一个结构体怎么算？
2. 为什么会有 padding？
3. 成员顺序会影响大小吗？
4. `alignas` 和 `alignof` 是做什么的？
5. 多继承的对象内存布局是什么样的？

## 原理

### 1. 对齐规则

每个类型有一个对齐值（`alignof(T)`）。对象或成员的地址必须是其对齐值的整数倍。结构体布局遵守两条规则：

1. 每个成员的偏移量是它自身对齐值的整数倍，不够就插入 padding；
2. 结构体总大小是「最大对齐要求（成员、基类、`alignas`）」的整数倍，末尾可能补 padding。

对基础类型，对齐值通常等于自身大小，但不超过编译器的默认上限（MSVC 默认 8，GCC x86-64 默认 16）。可以用 `alignas` 提高对齐；标准不允许用它降低自然对齐（降低要靠 `#pragma pack` 等扩展，可移植性差；`alignas(0)` 会被忽略）。

### 2. 结构体大小示例

```cpp
#include <iostream>

struct A { char c; int i; };        // c@0，pad 1-3，i@4，总大小 8
struct B { int i; char c; };        // i@0，c@4，pad 5-7，总大小 8
struct C { char a; double d; };     // a@0，pad 1-7，d@8，总大小 16
struct D { char a; char b; int i; };// a@0，b@1，pad 2-3，i@4，总大小 8

struct Bad  { char a; int b; char c; };  // 12 字节
struct Good { int b; char a; char c; };  // 8 字节

int main() {
    std::cout << sizeof(A) << ' ' << sizeof(B) << ' ' << sizeof(C) << ' '
              << sizeof(D) << ' ' << sizeof(Bad) << ' ' << sizeof(Good) << '\n';
    // 64 位常见输出：8 8 16 8 12 8
}
```

`Bad` 中间塞了一个 `int`，前后各产生 padding；把 `int` 放到最前面，`char` 紧跟其后，padding 就消失了。

### 3. alignas / alignof

- `alignof(T)`：查询类型的对齐要求；
- `alignas(n)`：指定变量或类型的对齐，`n` 必须是 2 的幂，且不能低于自然对齐（可以调高）。

```cpp
#include <iostream>

struct alignas(16) Vec4 {
    float x, y, z, w;
};

int main() {
    std::cout << sizeof(Vec4) << ' ' << alignof(Vec4) << '\n'; // 16 16
}
```

SIMD、DMA、缓存行对齐等场景常用 `alignas`。

### 4. offsetof

`offsetof(T, member)` 返回成员相对结构体起始地址的字节偏移，定义在 `<cstddef>`：

```cpp
#include <cstddef>
#include <iostream>

struct S {
    char a;
    int b;
    double c;
};

int main() {
    std::cout << offsetof(S, a) << ' '
              << offsetof(S, b) << ' '
              << offsetof(S, c) << '\n'; // 常见输出：0 4 8
}
```

`offsetof` 只对「标准布局类型」（standard-layout）有明确定义；含虚函数、虚基类，或非静态数据成员访问控制不一致的类型不要用。

### 5. 栈帧布局

函数调用时，栈帧通常包含：

- 调用者传入的参数（调用约定决定放寄存器还是栈）；
- 返回地址；
- 保存的帧指针 / 寄存器；
- 局部变量与临时对象；
- 对齐填充（保持栈指针对齐）。

具体布局依赖平台和调用约定（`cdecl`、`stdcall`、`x86-64 System V` 等），面试中给方向即可，不要死背某一种。

### 6. 空类与空基类优化

- 空类 `sizeof` 为 1，保证不同对象地址不同；
- 作为基类时，空基类子对象可以被优化掉（EBO），不占空间；C++20 的 `[[no_unique_address]]` 把同样的优化扩展到成员。

```cpp
#include <iostream>

struct Empty {};
struct WithEmptyBase : Empty { int x; };
struct WithEmptyMember { Empty e; int x; };

int main() {
    std::cout << sizeof(Empty) << ' '
              << sizeof(WithEmptyBase) << ' '
              << sizeof(WithEmptyMember) << '\n'; // 常见输出：1 4 8
}
```

### 7. 继承与多继承的布局

- 单继承：派生类对象 = 基类子对象 + 派生类成员，基类在前；
- 多继承：每个基类子对象按声明顺序排列，各自可能带自己的 vptr，派生类指针转成某个基类指针时要做地址调整；
- 虚继承：虚基类只保留一份，派生类通常通过 `vbptr`（虚基类表指针）定位共享的虚基类子对象。

```cpp
#include <iostream>

struct Base { int x; };
struct A : virtual Base { int a; };
struct B : virtual Base { int b; };
struct C : A, B { int c; };

int main() {
    std::cout << sizeof(Base) << ' ' << sizeof(C) << '\n'; // 实现相关，C 明显更大
}
```

### 8. 缓存行

CPU 以缓存行（常见 64 字节）为单位搬运数据。把高频访问的字段放在一起、避免伪共享（两个线程写同一缓存行里的不同变量），比抠几个字节的 padding 更能影响性能。

## 高频追问

**Q1：`sizeof(struct)` 怎么算？**
A：按成员顺序依次放置，每个成员偏移对齐到自身对齐值；总大小再补齐到最大成员对齐值的整数倍。

**Q2：为什么需要内存对齐？**
A：CPU 访问对齐地址通常只需一次总线事务，未对齐可能拆成多次甚至触发异常；对齐也是 ABI 的一部分，保证不同编译单元布局一致。

**Q3：成员顺序会影响结构体大小吗？**
A：会。把对齐要求大的成员放前面、小的放后面，通常能减少 padding。`Bad`（12 字节）和 `Good`（8 字节）就是例子。

**Q4：`alignas` 和 `alignof` 有什么区别？**
A：`alignof` 查询对齐值，`alignas` 指定对齐值。`alignas` 不能低于类型的自然对齐，只能调高（某些编译器允许 `#pragma pack` 降低，但可移植性差）。

**Q5：`offsetof` 有什么限制？**
A：只对标准布局类型有定义。含虚函数、虚基类，或非静态数据成员访问控制不一致（例如既有 public 又有 private）的类型不要用。全私有成员仍是 standard-layout，只是类外不能直接访问该成员；在类内或友元里 `offsetof` 仍可用。

**Q6：空类为什么大小是 1？空基类为什么能优化掉？**
A：大小至少为 1 是为了让不同对象地址不同；空基类子对象不包含数据，标准允许编译器把它优化掉（EBO），因此不占额外空间。

**Q7：多继承下 `A*` 和 `B*` 指向同一对象，地址为什么可能不同？**
A：`C` 对象里 `A` 子对象和 `B` 子对象位于不同偏移，指针转换时编译器会加上相应偏移。比较这类指针时不要直接比地址，按类型比较。

## 易错点与加分点

- 只记住「结构体大小 = 成员大小之和」，忽略 padding。
- 用 `offsetof` 测含虚函数的类，得到未定义结果。
- 以为 `alignas` 可以任意降低对齐（标准只保证能提高自然对齐）。
- 忽略缓存行和伪共享，只盯着几个字节的 padding。
- 能说出 `#pragma pack(1)` 会破坏可移植性和对齐访问性能。
- 知道多继承/vptr/vbptr 会改变布局，并链接到构造析构与多继承篇。
