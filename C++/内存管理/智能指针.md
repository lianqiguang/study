# 智能指针

> 一句话结论：智能指针用 RAII 管理堆对象生命周期；`unique_ptr` 独占所有权且零额外开销，`shared_ptr` 靠原子引用计数共享所有权但被管理对象本身并不线程安全，`weak_ptr` 用于观察和打破循环引用。

## 为什么考 / 怎么考

中级面试几乎必问。考察点不是「知道有哪几种」，而是所有权模型、控制块结构、线程安全边界，以及什么时候用错会泄漏或双重释放。典型追问链：

1. 三种智能指针分别解决什么问题？
2. `shared_ptr` 的引用计数存在哪？为什么是原子的？
3. 循环引用怎么产生、怎么解决？
4. `make_shared` 和 `shared_ptr(new T)` 有什么区别？
5. `shared_ptr` 线程安全吗？

## 原理

### 1. unique_ptr：独占所有权

- 一个对象同一时刻只能有一个 `unique_ptr` 持有；
- 不可拷贝，只能移动（move-only），所有权转移必须显式 `std::move`；
- 默认 deleter 是无状态空类，经空基类优化后，`sizeof(unique_ptr<T>)` 通常等于裸指针；
- 支持数组特化 `std::unique_ptr<T[]>`，析构时用 `delete[]`。

```cpp
#include <iostream>
#include <memory>

int main() {
    auto p = std::make_unique<int>(42);
    std::cout << sizeof(p) << ' ' << sizeof(int*) << '\n'; // 通常相同

    // std::unique_ptr<int> q = p;  // 编译错误：不能拷贝
    std::unique_ptr<int> q = std::move(p); // 所有权转移，p 变为空
}
```

**默认优先用 `unique_ptr`**：表达清晰、无引用计数开销、可编译期检查所有权。

### 2. shared_ptr：共享所有权与控制块

`shared_ptr` 由两部分组成：对象指针 + 指向**控制块**的指针。控制块通常包含：

- 强引用计数（有多少个 `shared_ptr` 持有对象）；
- 弱引用计数（有多少个 `weak_ptr` 观察对象）；
- deleter、allocator 等。

```cpp
#include <iostream>
#include <memory>

int main() {
    auto sp = std::make_shared<int>(10);
    std::weak_ptr<int> wp = sp;            // 弱引用不增加强计数

    std::cout << sp.use_count() << '\n';   // 1
    {
        auto sp2 = sp;                     // 强计数 +1
        std::cout << sp.use_count() << '\n'; // 2
    }
    std::cout << sp.use_count() << '\n';   // 1

    sp.reset();                            // 强计数归零，对象析构
    std::cout << (wp.expired() ? "expired" : "alive") << '\n'; // expired
}
```

`make_shared<T>(args...)` 把对象和控制块分配在同一块内存里：

- 优点：一次分配，缓存局部性更好，异常安全；
- 代价：只要还有 `weak_ptr` 存活，整块内存（包括对象所占空间）都不能释放，即使对象已经析构。

### 3. 线程安全边界（高频陷阱）

`shared_ptr` 的引用计数增减是**原子操作**，所以多个线程各自持有不同的 `shared_ptr` 副本、并发拷贝/析构是安全的。

但这**不等于对象线程安全**：

- 多个线程同时读写同一个被管理对象，仍需自己加锁；
- 多个线程同时读写**同一个 `shared_ptr` 实例**（比如对全局 `shared_ptr` 赋值）是数据竞争，不是线程安全的。

```cpp
#include <memory>

std::shared_ptr<int> g;

// 反例：两个线程同时调用 f() 会产生数据竞争
void f() {
    g = std::make_shared<int>(1); // 对同一个 shared_ptr 实例并发写，UB
}
```

对共享的 `shared_ptr` 变量做读写，要么加锁，要么用 `std::atomic<std::shared_ptr<T>>`（C++20）。

### 4. 循环引用与 weak_ptr

两个对象用 `shared_ptr` 互相持有，强计数永远不归零，析构函数不会执行：

```cpp
#include <iostream>
#include <memory>

struct B;

struct A {
    std::shared_ptr<B> b;
    ~A() { std::cout << "~A\n"; }
};

struct B {
    std::shared_ptr<A> a;
    ~B() { std::cout << "~B\n"; }
};

int main() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();
    a->b = b;
    b->a = a;   // 形成环：两个对象都泄漏
}
```

把其中一条边改成 `weak_ptr` 即可打破环：

```cpp
#include <iostream>
#include <memory>

struct B;

struct A {
    std::shared_ptr<B> b;
    ~A() { std::cout << "~A\n"; }
};

struct B {
    std::weak_ptr<A> a;   // 弱引用，不增加强计数
    ~B() { std::cout << "~B\n"; }
};

int main() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();
    a->b = b;
    b->a = a;   // 离开作用域后 a、b 正常析构
}
```

`weak_ptr` 不参与所有权，只观察：`expired()` 判断对象是否已销毁，`lock()` 原子地尝试提升为 `shared_ptr`，失败返回空。

### 5. enable_shared_from_this

类内部需要拿到「指向自己的 `shared_ptr`」时，继承 `std::enable_shared_from_this<T>`，调用 `shared_from_this()`：

```cpp
#include <iostream>
#include <memory>

class Node : public std::enable_shared_from_this<Node> {
public:
    std::shared_ptr<Node> self() { return shared_from_this(); }
};

int main() {
    auto n = std::make_shared<Node>();
    auto n2 = n->self();
    std::cout << n.use_count() << '\n'; // 2
}
```

前提是对象**已经由 `shared_ptr` 管理**。如果是栈对象或裸 `new` 后直接调用，会抛 `std::bad_weak_ptr`。

### 6. 自定义 deleter 与数组

非 `new` 分配的资源需要自定义 deleter：

```cpp
#include <cstdio>
#include <memory>

int main() {
    std::unique_ptr<FILE, decltype(&std::fclose)> fp(
        std::fopen("a.txt", "r"), &std::fclose);
    if (!fp) return 1;
    return 0;
}
```

数组特化：

```cpp
#include <memory>

int main() {
    std::unique_ptr<int[]> a(new int[10]);
    a[0] = 1;

    std::shared_ptr<int[]> b(new int[10]); // C++17 起支持
    b[0] = 2;
}
```

`unique_ptr` 的 deleter 类型是类型的一部分，会参与 `sizeof`；`shared_ptr` 的 deleter 存在控制块里，不改变 `shared_ptr` 本身的大小。

## 高频追问

**Q1：`shared_ptr` 的引用计数存放在哪里？**
A：在堆上的控制块里，不在 `shared_ptr` 对象内部。`shared_ptr` 对象本身只有两个指针（对象指针 + 控制块指针）。

**Q2：`make_shared` 和 `shared_ptr(new T)` 有什么区别？**
A：`make_shared` 把对象和控制块一次分配，少一次 `new`，更安全；但 `weak_ptr` 存活期间整块内存不能释放。`shared_ptr(new T)` 分配两次，对象内存可以在强计数归零时立即释放。

**Q3：循环引用会怎样？怎么解决？**
A：强计数互相持有，永远不归零，对象不析构、内存泄漏。把环上的一条边改成 `weak_ptr`。

**Q4：`weak_ptr` 如何判断对象是否还活着？**
A：`expired()` 返回是否已销毁；需要访问时用 `lock()`，它原子地提升为 `shared_ptr`，失败返回空。不要先 `expired()` 再解引用，中间对象可能被销毁。

**Q5：`shared_ptr` 能管理数组吗？**
A：C++17 起支持 `std::shared_ptr<T[]>`；更早版本需要传自定义 deleter（`std::default_delete<T[]>`）。但通常优先 `std::vector` 或 `unique_ptr<T[]>`。

**Q6：`shared_ptr` 是线程安全的吗？**
A：引用计数是原子的，不同 `shared_ptr` 副本跨线程操作安全；被管理对象和同一个 `shared_ptr` 实例的并发读写都不安全。

**Q7：同一个裸指针能构造两个 `shared_ptr` 吗？**
A：不能。会生成两个独立控制块，各自析构时都 `delete` 同一块内存，造成双重释放。必须从已有的 `shared_ptr` 拷贝或 `weak_ptr::lock()` 获得。

## 易错点与加分点

- `unique_ptr` 优先于 `shared_ptr`；只有确实需要共享所有权时才用引用计数。
- `make_shared` 的 `weak_ptr` 内存滞留问题，在大量弱引用场景要意识到。
- `shared_ptr` 不能替代 `unique_ptr` 做性能敏感路径，原子计数有开销。
- 不要对 `shared_ptr` 管理的对象再手动 `delete`。
- `enable_shared_from_this` 不是万能：栈对象调用会抛异常。
- 自定义 deleter 时注意捕获状态，deleter 会被拷贝/移动。
