# 异常安全

> 一句话结论：异常安全不是「不抛异常」，而是异常发生时对象仍处于合法状态、不泄漏资源；用 RAII 管资源、用 copy-and-swap 提供强保证、用 `noexcept` 标注不会抛的操作（尤其是移动构造和析构）。

## 为什么考 / 怎么考

中级岗位会考「异常安全」这个词背后的具体保证，而不是让你背概念。典型追问链：

1. 异常安全有哪几种保证？
2. copy-and-swap 为什么能提供强异常安全？
3. 移动构造为什么要 `noexcept`？
4. 构造函数抛异常会怎样？
5. 析构函数能抛异常吗？

## 原理

### 1. 异常传播与栈展开

`throw` 之后，运行时沿调用栈向上寻找匹配的 `catch`。每退出一层作用域，都会调用该作用域内已构造对象的析构函数（栈展开），这就是 RAII 能在异常路径上清理资源的原因。

没有匹配的 `catch` 时，调用 `std::terminate`。

### 2. 四种异常安全保证

| 保证 | 含义 |
|---|---|
| 不抛（nothrow） | 操作保证不抛异常 |
| 强保证（strong） | 操作失败时，对象保持操作前的状态（提交或回滚） |
| 基本保证（basic） | 失败时对象仍合法、不泄漏，但状态可能改变 |
| 无保证（none） | 失败后对象可能不可用 |

标准库容器大多提供强保证（如 `vector::push_back` 在扩容失败时保持原状），但并非所有操作都能做到。

### 3. 构造函数的异常安全

构造函数抛异常时，该对象**不会**被构造完成，析构函数不会执行；但已经构造完成的成员子对象和基类子对象会被析构。

因此，构造函数里如果手动 `new` 了多个资源，前一个可能泄漏：

```cpp
struct Bad {
    int* a;
    int* b;
    Bad() : a(new int[10]), b(new int[10]) {}   // b 抛异常时 a 泄漏
    ~Bad() { delete[] a; delete[] b; }
};
```

正确做法是让每个资源都由 RAII 成员管理（`std::vector`、`unique_ptr`），成员析构会自动清理。

### 4. copy-and-swap：强异常安全

复制赋值可以用「先拷贝、再交换」实现：

1. 按值接收参数（拷贝或移动构造，可能在进入函数前抛异常）；
2. 与 `*this` 交换（`swap` 标 `noexcept`）；
3. 旧资源随参数析构释放。

如果拷贝失败，异常发生在交换之前，`*this` 尚未改变，因此满足强保证：

```cpp
#include <algorithm>
#include <cstddef>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t n) : data_(new int[n]), n_(n) {}

    Buffer(const Buffer& other) : data_(new int[other.n_]), n_(other.n_) {
        std::copy(other.data_, other.data_ + n_, data_);
    }

    Buffer(Buffer&& other) noexcept : data_(other.data_), n_(other.n_) {
        other.data_ = nullptr;
        other.n_ = 0;
    }

    ~Buffer() { delete[] data_; }

    void swap(Buffer& other) noexcept {
        std::swap(data_, other.data_);
        std::swap(n_, other.n_);
    }

    Buffer& operator=(Buffer other) noexcept {   // 按值传参：拷贝或移动
        swap(other);
        return *this;
    }

private:
    int* data_;
    std::size_t n_;
};
```

注意：`operator=` 标 `noexcept` 只覆盖函数体内的操作；参数构造期间的异常发生在进入函数之前，不受它影响。

### 5. noexcept

`noexcept` 是编译期契约：函数承诺不抛异常，一旦抛出就调用 `std::terminate`。它影响：

- 容器扩容时是否优先移动（`move_if_noexcept`）；
- `swap`、移动构造、移动赋值、析构函数的异常安全；
- 编译器优化（可以省略栈展开信息）。

```cpp
#include <type_traits>

struct S {
    S(S&&) noexcept {}
    S& operator=(S&&) noexcept { return *this; }
    ~S() noexcept {}
};

static_assert(std::is_nothrow_move_constructible_v<S>);
```

### 6. 析构函数与异常

析构函数默认是 `noexcept`。异常一旦逃逸出析构函数，就会调用 `std::terminate`，栈展开期间同样如此。所以析构函数不应抛出异常；可能失败的操作应在析构前显式处理，或吞掉异常并记录日志。

### 7. catch 的正确写法

- 按 `const` 引用捕获，避免切片和多余拷贝；
- 派生类异常要写在基类之前，否则会被基类捕获；
- 需要继续向上传播时用 `throw;` 重新抛出当前异常，不要 `throw e;`（会切片并丢失原始类型）。

```cpp
#include <iostream>
#include <stdexcept>

void mayThrow() {
    throw std::runtime_error("boom");
}

int main() {
    try {
        mayThrow();
    } catch (const std::exception& e) {   // 按 const 引用捕获
        std::cout << e.what() << '\n';
        // throw;   // 需要继续传播时重新抛出
    }
}
```

### 8. 标准异常层次与自定义异常

`std::exception` 是根，常用派生类有 `std::runtime_error`、`std::logic_error`、`std::out_of_range`、`std::bad_alloc`。自定义异常通常继承 `std::runtime_error`：

```cpp
#include <stdexcept>

class MyError : public std::runtime_error {
public:
    using std::runtime_error::runtime_error;
};
```

`what()` 本身是 `noexcept` 的，不要在自定义异常里让它抛异常。

### 9. 异常 vs 错误码

- 异常适合「罕见、无法在本地处理」的错误，能把错误从深层调用栈带到有上下文的地方；
- 错误码适合「预期内、需要频繁检查」的情况，无栈展开开销；
- 禁用异常（`-fno-exceptions`）的嵌入式环境常用错误码，但标准库的部分组件会受影响。

## 高频追问

**Q1：异常安全有哪几种保证？**
A：不抛、强保证、基本保证、无保证。强保证要求失败后对象保持原状；基本保证要求不泄漏、状态合法。

**Q2：copy-and-swap 为什么能提供强异常安全？**
A：先在参数里完成可能抛异常的拷贝；成功后再用 `noexcept` 的 `swap` 替换当前对象。拷贝失败时当前对象尚未改变。

**Q3：移动构造为什么要 `noexcept`？**
A：`vector` 扩容用 `move_if_noexcept`：移动构造是 `noexcept` 时优先移动；否则，如果类型可拷贝，就退化为拷贝以保证强异常安全；只能移动的类型仍会移动，此时可能失去强保证。

**Q4：构造函数抛异常会怎样？**
A：该对象不会构造完成，析构函数不执行；已构造完成的成员和基类子对象会析构。构造函数内手动申请的资源如果不由 RAII 管理，就会泄漏。

**Q5：析构函数能抛异常吗？**
A：默认 `noexcept`，异常逃逸会 `std::terminate`，栈展开期间同样如此。析构函数不应抛出异常。

**Q6：`catch` 按值还是按引用？**
A：按 `const` 引用，避免切片和拷贝；派生类异常写在基类前面；重新抛出用 `throw;`。

**Q7：异常和错误码怎么选？**
A：异常适合罕见、跨层传播的错误；错误码适合预期内、频繁检查、禁用异常的环境。两者不要在同一接口里混用。

**Q8：基本保证和强保证的区别？**
A：基本保证只要求失败后对象合法、无泄漏，状态可以改变；强保证要求失败后对象和操作前完全一致。

## 易错点与加分点

- 把「异常安全」理解成「代码不抛异常」。
- 构造函数里手动管理多个资源，异常时泄漏。
- 移动构造忘记 `noexcept`：可拷贝类型的容器扩容退化为拷贝；只能移动的类型仍会移动，但可能失去强保证。
- 在析构函数里抛异常。
- `catch (Exception e)` 按值捕获导致切片。
- 能说出 copy-and-swap 的提交/回滚机制，以及它依赖 `swap` 不抛。
