# 编译链接

> 一句话结论：编译以翻译单元为单位、链接负责把多个目标文件合成程序；ODR 要求同一个实体在整个程序里只有一份定义，`inline` 和模板正是为了让定义能安全地出现在多个翻译单元里。

## 为什么考 / 怎么考

中级面试常从「为什么头文件里定义函数会重复定义」切入，追问 ODR、链接属性、静态库/动态库和模板为什么放头文件。典型追问链：

1. 声明和定义有什么区别？
2. 什么是 ODR？哪些写法会违反？
3. `static` 和匿名命名空间有什么共同点？
4. 模板为什么通常写在头文件里？
5. 静态库和动态库有什么区别？

## 原理

### 1. 翻译单元（TU）

一个源文件加上它 `#include` 进来的所有头文件，经过预处理后形成一个翻译单元。编译器独立编译每个 TU，生成目标文件；链接器再把目标文件和库合成可执行文件。

### 2. 声明与定义

- **声明**：告诉编译器「这个名字存在、类型是什么」，不分配存储；
- **定义**：真正创建实体（函数体、变量存储、类定义）。

```cpp
extern int global;          // 声明
int global = 42;            // 定义

int add(int, int);          // 声明
int add(int a, int b) {     // 定义
    return a + b;
}
```

一个变量可以声明多次，但只能定义一次。

### 3. 单一定义规则（ODR）

ODR 的核心：

- 同一个 TU 内，一个实体最多定义一次；
- 整个程序内，非 `inline` 的函数和变量只能有一份定义；
- 类、模板、`inline` 函数可以在多个 TU 中出现，但每份定义必须完全一致。

常见的 ODR 违规：

- 在头文件里定义非 `inline` 函数或全局变量，被多个 .cpp 包含；
- 同一个类在不同 TU 里定义不一致（例如受宏影响）；
- 非 `inline` 的静态成员变量在多个 TU 里重复定义。

```cpp
// 头文件中的正确写法：inline 允许定义出现在多个 TU
inline int square(int x) { return x * x; }
```

### 4. inline 的真实含义

`inline` 不只是「建议内联」：

- 它允许函数定义出现在多个 TU 中，链接器会合并；
- 它是给链接器的「可以重复定义」许可；
- 编译器是否真的内联是另一回事。

C++17 起还可以用 `inline` 变量在头文件里定义全局/静态成员：

```cpp
struct Config {
    inline static int value = 42;   // 头文件中安全定义
};
```

### 5. 链接属性

- **外部链接**：默认，名字对其他 TU 可见（普通函数、非 static 全局变量）；
- **内部链接**：只在当前 TU 可见，包括命名空间作用域的 `static` 变量/函数、匿名命名空间内的名字、`const` 全局变量（默认内部链接，除非 `extern`）。

```cpp
namespace {
int hidden = 0;   // 内部链接，其他 TU 看不到
}
```

```cpp
static int counter = 0;   // 内部链接（旧的 C 风格写法）
```

内部链接的好处是避免符号冲突；代价是每个 TU 各有一份，不能跨 TU 共享。

### 6. 头文件保护

同一个头文件可能被间接包含多次，需要防止重复展开：

```cpp
#ifndef MY_HEADER_H
#define MY_HEADER_H

// 声明

#endif
```

大多数编译器也支持 `#pragma once`，更简洁但不是标准；两种方式可以同时用。更重要的是「include what you use」：用到什么就包含什么，不要依赖其他头文件的传递包含。

### 7. 静态初始化顺序

不同 TU 的全局/静态对象初始化顺序未指定，跨 TU 依赖可能读到未初始化的值（static initialization order fiasco）。用函数内局部 `static`（首次使用时构造）规避，细节见 [const / static / volatile](../基础/const-static-volatile.md)。

### 8. 名字修饰与 extern "C"

C++ 支持重载，编译器会把参数类型编码进符号名（name mangling）。C 没有重载，符号名就是函数名本身。要让 C++ 代码被 C 调用（或反之），用 `extern "C"` 关闭修饰：

```cpp
extern "C" int add(int a, int b);
```

注意：`extern "C"` 的函数不能重载，因为符号名相同。

### 9. 静态库与动态库

- **静态库**（Linux `.a`，Windows `.lib`）：一组目标文件的归档，链接时把用到的目标文件复制进可执行文件；部署简单，体积大，更新需要重新链接。
- **动态库**（Linux `.so`，Windows `.dll`）：运行时加载，多个程序共享；体积小，但需要处理运行时查找路径和 ABI 兼容。

静态库链接有顺序要求：依赖者写在被依赖者前面；循环依赖可用 `--start-group/--end-group`（GNU ld）。动态库常见问题是运行时找不到库（`LD_LIBRARY_PATH` / `rpath` / PATH）。

### 10. 未定义符号与重复符号

- **未定义符号（undefined reference）**：声明了但没链接到定义，常见于漏链接库、库顺序不对、忘记编译某个 .cpp。
- **重复符号（multiple definition）**：同一个非 inline 实体定义了多次，通常是头文件里放了定义。

### 11. 模板为什么放在头文件

模板在实例化时才生成代码，编译器必须在实例化点看到完整定义，因此模板定义通常放在头文件。也可以用显式实例化把定义放在 .cpp：

```cpp
template <typename T>
T twice(T x) { return x * 2; }

template int twice<int>(int);   // 显式实例化
```

代价是只支持预先列举的类型，失去隐式实例化的灵活性。

### 12. 优化与调试

- `-O0` 便于调试，`-O2`/`-O3` 开启优化；
- `-g` 生成调试符号；
- LTO（链接时优化）让编译器跨 TU 优化，编译更慢但可能更快；
- `-fvisibility=hidden` 减少动态库导出的符号，加快加载并避免冲突。

## 高频追问

**Q1：声明和定义有什么区别？**
A：声明只引入名字和类型，不分配存储；定义创建实体。变量可以多次声明、只能定义一次；函数声明可以多次，定义只能一次（`inline` 除外）。

**Q2：什么是 ODR？**
A：单一定义规则：同一 TU 内实体最多定义一次；整个程序内非 inline 函数/变量只能有一份定义；类、模板、inline 函数可多份但必须一致。

**Q3：`static` 和匿名命名空间有什么共同点？**
A：都让名字具有内部链接，只在当前 TU 可见，避免跨 TU 符号冲突。匿名命名空间是更现代的写法。

**Q4：模板为什么通常写在头文件里？**
A：模板在实例化时需要完整定义；如果定义在 .cpp 里，其他 TU 看不到，无法实例化。可以用显式实例化把定义放 .cpp，但只支持列举的类型。

**Q5：静态库和动态库有什么区别？**
A：静态库在链接时复制进可执行文件，部署简单、体积大；动态库运行时加载、可共享、体积小，但要处理查找路径和 ABI 兼容。

**Q6：未定义符号和重复符号分别怎么产生？**
A：未定义符号通常是漏链接库、库顺序错误或漏编译源文件；重复符号通常是非 inline 定义放进了被多次包含的头文件。

**Q7：`extern "C"` 的作用？**
A：关闭 C++ 名字修饰，让符号按 C 规则命名，便于 C/C++ 互相调用；代价是不能重载。

**Q8：`inline` 函数一定会被内联吗？**
A：不一定。`inline` 主要给链接器「可以重复定义」的许可，是否内联由编译器根据优化级别、函数大小等决定。

## 易错点与加分点

- 把头文件里的普通函数/全局变量当成「只定义一次」，导致重复符号。
- 以为 `static` 只影响存储位置，忽略内部链接。
- 静态库链接顺序写反，出现未定义符号。
- 在 .cpp 里定义模板，其他 TU 实例化失败。
- 用 `#pragma once` 就忽略「include what you use」。
- 能说出 `inline` 的链接语义，而不只是「建议内联」。
