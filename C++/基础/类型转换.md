# 类型转换

> 一句话结论：优先使用四种具名转换——`static_cast` 管相关类型，`dynamic_cast` 管多态类型的运行时检查，`const_cast` 只增删 const，`reinterpret_cast` 做底层重解释；C 风格转换尽量不用。

## 为什么考 / 怎么考

类型转换是「C++ 比 C 安全在哪」的典型考点。面试官通常先问四种 cast 的区别，再追问 `dynamic_cast` 为什么要求虚函数、`const_cast` 什么时候安全、C 风格转换危险在哪。典型追问链：

1. 四种 cast 分别用在什么场景？
2. `static_cast` 下行转换安全吗？
3. `dynamic_cast` 失败会怎样？
4. `const_cast` 去掉 const 后修改对象会怎样？
5. 为什么说 C 风格转换危险？

## 原理

### 1. 隐式转换与 explicit

编译器会自动做很多转换：整数提升、`int` 到 `double`、派生类指针到基类指针、临时对象绑定到 const 引用等。单参数构造函数如果不加 `explicit`，会带来意外的隐式转换：

```cpp
#include <iostream>

struct S {
    explicit S(int) {}
};

int main() {
    S s1(1);        // 直接初始化
    // S s2 = 1;    // 错误：explicit 禁止隐式转换
    (void)s1;
}
```

### 2. static_cast

用于「相关类型」之间的转换，编译期完成，**不做运行时检查**：

- 数值类型转换：`int` → `double`、`enum` → 整数；
- 上行转换：派生类指针/引用 → 基类，安全；
- 下行转换：基类 → 派生类，**不检查实际类型**，转错就是未定义行为；
- `void*` ↔ `T*`；
- 调用显式构造函数。

```cpp
#include <iostream>

struct Base { int b = 1; };
struct Derived : Base { int d = 2; };

int main() {
    Derived d;
    Base* pb = static_cast<Base*>(&d);        // 上行：安全
    Derived* pd = static_cast<Derived*>(pb);  // 下行：不做检查
    std::cout << pd->d << '\n';
}
```

### 3. dynamic_cast

用于多态类型的安全下行/交叉转换，依赖 RTTI，运行时检查实际类型：

- 要求源类型至少有一个虚函数（多态类型）；
- 指针转换失败返回 `nullptr`；
- 引用转换失败抛 `std::bad_cast`；
- 有运行时开销，高频路径慎用。

```cpp
#include <iostream>
#include <typeinfo>

struct Base { virtual ~Base() = default; };
struct Derived : Base { int d = 7; };
struct Other : Base { int o = 8; };

int main() {
    Base* p = new Derived;

    if (auto* d = dynamic_cast<Derived*>(p)) {
        std::cout << d->d << '\n';   // 7
    }
    if (auto* o = dynamic_cast<Other*>(p)) {
        std::cout << o->o << '\n';   // 不执行：转换失败返回 nullptr
    }

    try {
        auto& r = dynamic_cast<Other&>(*p);  // 失败抛 bad_cast
        (void)r;
    } catch (const std::bad_cast&) {
        std::cout << "bad_cast\n";
    }

    delete p;
}
```

### 4. const_cast

只用于增删 `const` / `volatile` 限定，不改变类型本身。常见用途是调用只接受非 const 参数的旧接口。

**关键前提**：只有当底层对象本身不是 const 时，去掉 const 后修改才是安全的；修改一个真正 const 的对象是未定义行为。

```cpp
#include <iostream>

void print(const int& x) {
    int& y = const_cast<int&>(x);
    // y = 1;   // 如果 x 指向真正的 const 对象，这里就是 UB
    std::cout << y << '\n';
}

int main() {
    int a = 5;
    print(a);
}
```

### 5. reinterpret_cast

做最低层的「重新解释」，不改变值，只改变编译器看待这段比特的方式：

- 指针 ↔ 整数（`std::uintptr_t`）；
- 不相关指针类型之间转换；
- 函数指针转换。

它高度依赖平台和 ABI，除「转换出去再转回来」外很少可移植：

```cpp
#include <cstdint>
#include <iostream>

int main() {
    int a = 42;
    std::uintptr_t addr = reinterpret_cast<std::uintptr_t>(&a);
    int* p = reinterpret_cast<int*>(addr);
    std::cout << *p << '\n'; // 42
}
```

### 6. C 风格转换为什么危险

C 风格 `(T)x` 会依次尝试 `const_cast`、`static_cast`、`reinterpret_cast`，只要有一种能编过就用。它可能在你不注意时去掉 const，或做不相关的重解释，而且代码里看不出来到底用了哪种语义。C++ 中统一用四种具名转换表达意图。

## 高频追问

**Q1：四种 cast 的区别？**
A：`static_cast` 编译期、相关类型、无运行时检查；`dynamic_cast` 运行期、多态类型、失败可检测；`const_cast` 只改 const/volatile；`reinterpret_cast` 底层重解释、平台相关。

**Q2：`dynamic_cast` 为什么要求多态类型？**
A：它依赖 RTTI，而 RTTI 信息通常挂在 vtable 上；没有虚函数的类不是多态类型，无法在运行时确定实际类型。

**Q3：`const_cast` 什么时候是安全的？**
A：只在底层对象本身不是 const 时才安全，例如函数收到 `const T&`，但实参是非 const 对象。修改真正的 const 对象是 UB。

**Q4：`reinterpret_cast` 的典型用途？**
A：指针与整数互转、与硬件寄存器地址交互、序列化底层字节；除往返转换外，结果依赖平台，不应作为常规手段。

**Q5：C 风格转换为什么危险？**
A：它会隐式尝试多种转换，可能悄悄去掉 const 或做不相关重解释，阅读代码时无法判断意图，也绕过了编译器的类型检查提示。

**Q6：`static_cast` 下行转换安全吗？**
A：不安全。它不做运行时检查，如果基类指针实际指向的不是目标派生类，结果未定义。不能确定实际类型时用 `dynamic_cast`。

**Q7：`dynamic_cast` 的开销来自哪里？**
A：运行时类型检查和 RTTI 查表；在频繁调用的热路径上可能明显，设计上优先用虚函数而非反复 `dynamic_cast`。

## 易错点与加分点

- 用 `static_cast` 做不确定的下行转换，转错不自知。
- 以为 `const_cast` 能安全修改任何 const 对象。
- 把 `reinterpret_cast` 当通用的指针转换工具，忽略平台差异。
- 在禁用 RTTI 的构建里使用 `dynamic_cast`（编译失败或行为受限）。
- 能说出 `explicit` 抑制隐式转换、避免意外构造。
- 知道「能用虚函数解决的分派，不要用 `dynamic_cast` 硬转」。
